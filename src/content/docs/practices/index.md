The practices support the pillars, each with a class of tools beyond the ones the pillars rely on:

- **[Skills](/api4c-framework/practices/skills/)** support the [consistency](/api4c-framework/pillars/consistency/) and [continuity](/api4c-framework/pillars/continuity/) pillars by checking specifications against [guides](/api4c-framework/documents/guides/) and changes against [policies](/api4c-framework/documents/policies/) where linters and detectors fall short, and by handing checks over to them once code can express those checks.
- **[Toolkits](/api4c-framework/practices/toolkits/)** support the [continuity](/api4c-framework/pillars/continuity/) and [conformance](/api4c-framework/pillars/conformance/) pillars with SDKs and CLIs that absorb API changes behind stable interfaces, so consumers update toolkits instead of their code, and that expose only what contracts describe.
